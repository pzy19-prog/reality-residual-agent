# DIAG-02：未发出抓取命令的静默路径（仅 dev seeds）

## 范围与定义

- 只读取 `config/dev_seeds.json` 的 seed 0–129；没有执行 eval seeds，也没有读取 `bench.json`。
- 静默失败沿用 `diag/dev_bench.json` 定义：零升级 episode 中未成功抓取的生成物体。
- `include_trace=True` 才生成 `failure_trace`；默认路径不生成 trace。trace 只读取状态并写入 receipt，不写回或影响控制判断。
- `decision_sample_count` 是对象在记录决策前收到的样本数；无命令时，决策时刻为 episode 最后一次样本。`window_remaining_time = predicted_window.end - decision_time`，正数表示窗口尚未来到，负数表示已过。
- `compensated_predicted_window` 在 compensation=on 时是修正后窗口；off 时是原计划窗口。每个对象的 plant 时钟从 0 开始，前一对象时间用 episode 全局时间表示；模拟器无抓取耗时，成功执行时刻即抓取结束时刻。前一对象未成功时该字段为 null。

## src 命令路径清单

| 文件:行 | 路径 | 触发条件与结果 |
|---|---|---|
| `src/rra/evidence/episode.py:47-51` | 每个 target 首次观测时计算一次 ETA；后续重复使用基准 plan，仅更新 observation time 并逐样本运行 corrector。 | estimator 未就绪没有取消计划或命令的分支。 |
| `src/rra/evidence/episode.py:53-62` | correction reason 含 `ESCALATE:` 时设 `safe_stop=True`。 | 残差越过固定安全阈值后，本 episode 后续对象都不发命令；该 episode 有 escalation。 |
| `src/rra/evidence/episode.py:103-104` | 唯一命令门：`not safe_stop`、target 不在 `attempted_targets`、且 `abs(observation.time - applied_plan.expected_arrival_time) <= dt/2` 三项须同时成立。 | 任一失败，本样本不发命令。时间窗没有覆盖任何观测样本时，对象到 episode 结束仍未命令；已经尝试过的对象不重试。 |
| `src/rra/evidence/episode.py:112-150` | 通过命令门后才构造 `Command` 并执行；执行后将 target 记为 attempted。 | controller 拒绝边界外命令会 safe-stop 并升级；边界内但物理窗口未命中返回 `missed pick window`，不会升级或重试。 |
| `src/rra/evidence/episode.py:153-169` | 循环结束后统计 successes 与 escalations。 | 未成功的生成物体计入失败；所选集合仅保留零升级 episode。 |
| `src/rra/sim/world.py:80,106-111` | 时间为 `step_index * dt`；达到 `episode_steps` 后 step 归零并切换 target。 | 每个对象各自使用 0–7.9s 局部时间；最后一个对象的预测窗可能晚于最后一个样本。 |

| `src/rra/controller/control.py:43-60` | 检查 speed/x/y 边界；通过后比较位置/时间误差与 tolerance。 | 边界拒绝是在命令已生成之后发生并触发升级；已接受但物理窗口未命中属于已发命令失败。 |

静态检查：src 中没有独立的“估计器就绪门”、可行性检查丢弃门或相邻物体冲突门。`attempted_targets` 只阻止同一对象重复尝试。本次未发命令失败来自时间窗门没有命中观测样本；moving/load 集合的失败对象都发过命令，controller 原因是 `missed pick window`。
